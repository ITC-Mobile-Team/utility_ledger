# Data Model: Профіль — тема застосунку та дрібні правки

## ThemePreference

Вибір теми користувачем.

| Поле | Тип | Правила |
|---|---|---|
| значення | `'light' \| 'dark' \| 'system'` | типово `'system'`; невідоме, пошкоджене чи відсутнє значення в сховищі читається як `'system'` |

- **Сховище**: `KeyValueStorage`, ключ `themePreference`, значення — рядок як є.
- **Відображення в `Appearance.setColorScheme`**: `light` → `'light'`, `dark` → `'dark'`, `system` → `'auto'`.
- **Підписи**: `light` — «Світла», `dark` — «Темна», `system` — «Як у системі» (рядок «Тема» в профілі й картки на екрані «Тема»).
- **Життєвий цикл**:
  - старт: читається до першого рендеру; якщо в сховищі висить `pendingWipe = 'true'` — береться `system`;
  - вибір на екрані «Тема»: одразу застосовується і пишеться в сховище;
  - «Вийти» / «Видалити акаунт»: ключ стирається в `wipeLocalData()`, стан у памʼяті скидається на `system` через `resetAppearance()`.

## OutageSetupStatus

Обчислюється з наявного `OutageSettings` (`city`, `queues`); окремо не зберігається.

| Значення | Умова | Текст статусу в профілі |
|---|---|---|
| `noCity` | `settings.city` порожнє | «Місто й черги не налаштовані» |
| `noProvider` | місто є, `getProviderForCity(city)` не знайшов постачальника | «Постачальник для вашого міста ще не доданий» |
| `noQueues` | постачальник є, серед `settings.queues` немає жодної черги з `provider.queues` | «Черги не вибрані» |
| `ready` | постачальник є і вибрана щонайменше одна його черга | — (статус не показується) |

Умови перевіряються згори донизу; перше збіжне значення — результат.

## Наявні сутності, яких торкається фіча

- **OutageSettings** (`src/services/outages/types.ts`) — лише читається; форма не змінюється.
- **Ключі, які стирає `wipeLocalData()`** — до наявних (`ledgerState`, `outageSettings`, `outageSchedule:<id>`, `userProfile`, `authUser`, `hasSeenOnboarding`, `pendingWipe`) додається `themePreference`.
