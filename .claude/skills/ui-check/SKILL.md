# UI-перевірка RN-застосунку з економією токенів

`SKILL_DIR` — каталог цього файлу (`.claude/skills/ui-check`). Усі команди викликай через обгортку
`"$SKILL_DIR"/scripts/ui` **з кореня проєкту**: вона виправляє застарілий `DEVELOPER_DIR`
(інакше падає навіть `/usr/bin/python3`) і запускає `ui.py` (stdlib, Python 3.9+).

Скрипт сам читає `app.json`: bundle id (`expo.ios.bundleIdentifier`), схему deep link (`expo.scheme`)
і схему dev-client (`exp+<slug>`). Перевизначення: `UI_BUNDLE`, `UI_SCHEME`, `UI_DEV_SCHEME`,
`UI_METRO` (за замовчуванням `http://localhost:8081`), `UI_SIM` (UDID, якщо запущено кілька симуляторів).

## Чому так

| Спосіб | Обсяг у контексті |
|---|---|
| `snapshot_ui` verbose JSON | ~80 КБ ≈ 25k токенів |
| `ui screen` | ~1 КБ ≈ 350 токенів, з текстами |
| Крок `ui run` | 0 рядків при успіху; 1 рядок + шлях до скріншота при FAIL |
| Скріншот iOS Simulator `control` (повний PNG) | ≈ 1500 токенів |
| `ui shot` повний екран (scale 0.6) | ≈ 170 токенів |
| `ui shot id=…` (обрізаний компонент) | 10–150 токенів |

Звідси правила:

1. **Не викликай MCP `snapshot_ui`, `screenshot` і `control screenshot` напряму.** Тільки `ui`. Панель симулятора (`control attach`) для користувача відкривати можна — вона не витрачає токенів.
2. **Дії — за селекторами, не за elementRef і не за координатами.** Скрипт сам знімає snapshot і шукає елемент.
3. **Сценарій — одним `ui run`.** Не повертай керування моделі між кроками. Між кроками ніяких скріншотів.
4. **Скріншот — лише для того, чого немає в дереві**: кольори, шрифти, відступи, обрізаний текст, звірка з канвасом (`docs/design.md`). Обрізаний до компонента, один раз у кінці.
5. Якщо FAIL-рядка достатньо, щоб зрозуміти причину, **не відкривай скріншот падіння**.

## Порядок роботи

1. `ui doctor` — один рядок: Xcode, симулятор, чи встановлено застосунок, чи працює Metro, що на екрані (`app` чи `dev-launcher`).
   - `metro=off` → попроси користувача запустити `npx expo start` або запусти його у фоні сам. Не запускай другий Metro, якщо порт 8081 уже зайнятий.
   - `app=MISSING` або змінився нативний код (новий пакет з нативним модулем, `app.json`, config plugins) → потрібна нова dev-збірка: `npx expo run:ios`. Збирай лише коли користувач попросив.
   - Зміни лише в JS/TS не потребують збірки: Fast Refresh підхоплює їх сам. Якщо стан застряг — `launch`.
2. Знайди селектори потрібного екрана **один раз**: `ui screen --grep 'Додати|Зберегти'`.
   `--grep` фільтрує вивід регулярним виразом, `--limit N` обрізає його, `--all` показує й елементи без id та тексту (і смуги прокрутки).
3. Запиши сценарій у `/private/tmp/ui-check/<feature>.flow`. Повторно придатні сценарії зберігай у `$SKILL_DIR/flows/` (вони в Git поруч із кодом, бо залежать від testID).
4. `ui run <feature>.flow` друкує лише FAIL/BLOCKED, рядки `shot` і підсумок `PASS 11/11 steps in 39s`.
   `-v` друкує кожен крок, `-k` продовжує після падіння.
5. Для візуальної звірки прочитай Read-ом лише потрібний `shot` і порівняй з канвасом.
6. Разовий крок без файлу: `ui do 'tap id=x' 'see Готово'`.

Приклад — `$SKILL_DIR/flows/smoke.flow` (проходить усі вкладки).

## Селектори

- `id=objects.card.0` — точний testID (найкраще).
- `label=Додати адресу`, `value=1`, `role=button`; `~=` означає «містить» без урахування регістру (`label~=Листопад`).
- `text~=Ваші адреси` — будь-який елемент, що містить текст у label або value.
- Поєднання через `&`: `role=tab&label=Світло`; `#N` вибирає N-й збіг (`…#1`).
- Слово без `=` — точний id або label.
- Враховуються лише видимі елементи. Якщо збігів кілька, скрипт повертає BLOCKED з кандидатами. Якщо жодного — FAIL з 1–3 найближчими id/label.

### Як RN-елементи виглядають у дереві

- `Pressable` (з `@/components`) — це один accessible-елемент: `role=other`, а label — тексти всіх дочірніх `Text` через кому (`other label=iPhone 17 Pro, Листопад заповнено, ⚡, …`). Окремих `Text` усередині **немає**, тому шукай `label~=iPhone`, а не `label=iPhone 17 Pro`.
- З `accessibilityRole="button"` елемент стає `role=button`.
- Нативні таби — `role=tab` з `value=1` на активному. Заголовок екрана часто має той самий текст, що й таб: `tap label=Обʼєкти` обирає таб (бо в нього є дія `tap`), а для перевірки пиши `check role=tab&label=Обʼєкти value=1`.
- Fabric показує кожен `Text` двічі з однаковою рамкою — скрипт залишає один.

## Кроки `.flow`

Один крок на рядок, `#` на початку — коментар. Опції у форматі `ключ=значення` можна писати в будь-якому місці рядка.

```
launch                       # перезапуск: dev-збірка підключається до Metro напряму, чекає на рендер JS (timeout=40)
launch keep                  # без terminate, просто вивести на передній план
open /outage-settings        # маршрут Expo Router → utilityledger://outage-settings (групи (tabs) тощо не пишуться)
open utilityledger://profile # або повний URL
tap id=objects.nav.add       # timeout=5 за замовчуванням: чекає появи елемента
hold label~=iPhone           # довге натискання
type id=objectForm.name "Dacha"  # append — дописати, а не замінити; лише латиниця, див. нижче
tap id=reading.value | keys 01234    # набір у поле з фокусом (прихований інпут барабана й суми)
key 42 count=4                       # натиснути клавішу за HID-кодом (42 — Backspace, 40 — Return) 4 рази в полі з фокусом; HID симулятора може зависати — перевіряй результат `check`-ом, `axe key` на ньому не завжди спрацьовує
swipe id=object.screen up distance=0.6
scrollto id=object.month.2026-01 within=id=object.screen dir=up max=8
wait id=outageSettings.screen timeout=10
gone label~=Завантаження
see Ваші адреси              # текст на екрані (nosee — відсутній)
check role=tab&label=Світло value=1    # label=… value=… label~=… enabled disabled count=N
shot id=objects.card.0 name=card scale=1.5   # crop до елемента; rect=x,y,w,h у points; pad=8
shot                                   # весь екран, scale 0.6
button home | sleep 0.5 | screen grep=…
```

## Відкрити екран одразу, без проходу по ланцюжку

Будь-який екран відкривається deep link'ом за його шляхом у `src/app/` (групи в дужках не пишуться, `[param]` — значення, решта параметрів — query):

```
launch
open /mw0spa9l-45k71j/2026-11/reading?serviceId=mw0tdfq7-p5rsf5
wait id=reading.screen
```

Це ~2 с замість трьох тапів по ~7 с. Токенів у `ui run` обидва способи на успіху не витрачають, тож різниця в часі й стабільності: менше кроків, менше місць для падіння. Але в стеку лише відкритий екран — «Назад» веде до кореня вкладки, а не на попередній екран ланцюжка. Якщо перевіряєш саме навігацію, проходь тапами.

id адрес і послуг — у даних застосунку (AsyncStorage, ключ `ledgerState`):
`"$(xcrun simctl get_app_container booted com.bogdanpoh.utility-ledger data)/Library/Application Support/com.bogdanpoh.utility-ledger/RCTAsyncLocalStorage_V1/"` — `manifest.json`, великі значення лежать у файлі з md5 ключа. Читай лише `id` і назви, не весь стан.

## Введення тексту

- `type` і `keys` друкують через HID-клавіатуру симулятора: **лише символи US-клавіатури** (кирилицю AXe не приймає), а літери проходять через розкладку апаратної клавіатури симулятора — з українською розкладкою `Dacha` стає `Вфсрф`. Цифри від розкладки не залежать. Для текстових полів у сценаріях бери цифри або латиницю й вимкни в Simulator «I/O → Keyboard → Use the Same Keyboard Language as macOS».
- Барабан показника й велика сума мають прихований `TextInput` (opacity 0), якого iOS не показує в дереві. testID стоїть на видимому блоці: `tap id=reading.value`, потім `keys 16253`; сума — `keys 125`.
- Якщо після набору поле не змінилось (`check … value=` FAIL), а поле у фокусі — HID-клавіатура симулятора «зависла»: вона не відновлюється перезапуском застосунку. Скажи користувачу, що треба перезапустити Simulator, і не повторюй набір у циклі.

`scale` — кількість пікселів на point. На 1.0 текст 13–17 pt добре читається. Нижче 0.5 дрібний текст губиться.

## testID

Сценарій настільки дешевий і стабільний, наскільки стабільні testID. Основні екрани їх уже мають (перелік префіксів — у `docs/patterns/test-ids.md`), тож бери `id=…`, а `label~=…` — лише для даних (назви міст, місяців) і нативних табів. Якщо фіча, яку тестуєш, не має testID на ключових елементах, **запропонуй** додати їх (не додавай мовчки).

- `testID` на iOS стає accessibility identifier (`id=` у селекторі). VoiceOver його не читає.
- `ui screen` у кінці виводить «N tappable without id» — скільки інтерактивних елементів без testID.

## Відомі особливості

- **Замок натискань 500 мс** (`src/components/pressable.tsx`): друге натискання протягом 500 мс після першого ігнорується. `ui` сам тримає між тапами щонайменше 0.6 с (`UI_PRESS_GAP`). Якщо тап «не спрацював» одразу після іншого — причина тут.
- **Dev launcher.** Якщо Metro не працював, коли застосунок стартував, замість застосунку відкривається екран «DEVELOPMENT SERVERS». Будь-який крок тоді повертає BLOCKED з підказкою; запусти Metro і зроби `launch`.
- **LogBox і RedBox** перекривають низ екрана або весь екран. Якщо FAIL дивний — подивись `ui screen --grep 'Error|Warning'`, а причину шукай у виводі Metro.
- Анімації Reanimated і переходи навігації тривають ~0.3–0.5 с: використовуй `wait`/`see` з таймаутом замість `sleep`.
- Кожен `tap` займає ~6–8 с: XcodeBuildMCP після дії сам знімає snapshot. Це час, а не токени, але не роби зайвих кроків.
- XcodeBuildMCP `tap` на таб-барі iOS 27 повідомляє про успіх, але нічого не робить. Тому `ui` спершу використовує `touch` (down+up у центрі елемента).
- `sips` мовчки ігнорує обрізку, якщо вона доходить до краю зображення. Скрипт обрізає на 1 px менше і перевіряє розмір результату.
- Демон `xcodebuildmcp` запам'ятовує `DEVELOPER_DIR`, з яким його запустили. Якщо AXe скаржиться на Xcode, `ui` один раз перезапускає демон.
- Не запускай `ui` паралельно з ручними тапами чи іншим агентом у тому самому симуляторі.
- Після перевірки видали `/private/tmp/ui-check/`, якщо скріншоти більше не потрібні.

Залежності: Xcode у `/Applications`, `xcodebuildmcp` CLI (`brew install xcodebuildmcp`), один запущений симулятор із встановленою dev-збіркою.

Код результату: 0 — успіх, 1 — FAIL (перевірка не пройшла), 2 — BLOCKED (інструмент, передумова, dev launcher або неоднозначний селектор).
