# Utility Ledger Constitution

## Core Principles

### I. Expo за документацією своєї версії

Застосунок — Expo/React Native для iOS та Android. Мажорна версія SDK — це версія пакета `expo` у `package.json`.
Перед кодом, що торкається Expo, EAS або React Native API, MUST звіритися з документацією саме цієї версії
(`https://docs.expo.dev/versions/v<major>.0.0/`, індекс `https://docs.expo.dev/llms.txt`), а не з памʼяттю.
Нові залежності додаються лише через `npx expo install`, не через `npm install`. Вбудованим модулям Expo
віддається перевага над сторонніми бібліотеками; якщо потрібна стороння — план MUST пояснити, чому модуль Expo не підходить.

### II. Expo Router і структура `src/`

Навігація — лише Expo Router. Кожен файл у `src/app/` — екран, `_layout.tsx` — навігатор.
Не-маршрутний код (компоненти, хуки, сервіси, утиліти) MUST жити поза `src/app/`
(`src/components`, `src/views`, `src/hooks`, `src/services`, `src/storage` тощо).

### III. Нативне налаштування лише через CNG

Каталоги `ios/` та `android/` генеруються (Continuous Native Generation) і MUST NOT редагуватися вручну.
Нативна поведінка налаштовується в `app.json` і config plugins. План MUST вказати, чи зміна
потребує нової development build (нативний модуль), чи доставляється OTA-оновленням.

### IV. Дизайн і патерни — джерело правди для екранів

Макети екранів — канвас Claude Design (посилання і як читати — `docs/design.md`). Кожен новий або змінений
екран MUST бути звірений з відповідним артбордом; план посилається на артборд.
Узгоджені патерни (клавіатура, вибір значень, навбар, таб-бар, свайпи, кнопки, Reanimated, відключення тощо) —
`docs/patterns/README.md`. Рішення MUST їм відповідати. Якщо зміна вводить або змінює патерн — у тій самій зміні
оновлюється файл у `docs/patterns/` і індекс `README.md` (окрема задача в `tasks.md`).

### V. Українська мова

Інтерфейс застосунку український; сценарії в специфікаціях описують поведінку з погляду користувача
з українськими текстами як у дизайні. Усі артефакти Spec Kit (spec, plan, tasks, checklists) пишуться українською;
ключові слова вимог (MUST, SHOULD, Given/When/Then) та службові заголовки шаблонів можна лишати англійською.

### VI. Lint і typecheck перед «готово»

Задача або фіча не вважається виконаною, доки `npx expo lint` і `npx tsc --noEmit` не завершуються без помилок.
Остання задача кожного `tasks.md` — запустити обидві команди й виправити помилки.

## Обсяг і формат артефактів

- `spec.md` — коротко: які екрани в `src/app/` зачіпає фіча і що лишається поза обсягом.
- `plan.md` — артборди дизайну, застосовні файли `docs/patterns/`, потреба в development build, точні шляхи файлів.
- `tasks.md` — задачі з точними шляхами; задача на `docs/patterns/`, якщо патерн змінюється; фінальна задача — lint і typecheck.

## Процес

- Перед версткою екрана прочитати відповідний файл `docs/patterns/` і артборд з `docs/design.md`.
- Зміни комітяться одразу після реалізації; коміт, що змінює патерн, містить і оновлений файл `docs/patterns/`.
- Після завершення фічі в `spec.md` ставиться **Status**: Implemented і коротко підсумовується українською, що змінилося.

## Governance

Ця конституція має пріоритет над іншими практиками Spec Kit у проєкті; `AGENTS.md` лишається основною
інструкцією для агентів, а конституція її не суперечить. Кожен `plan.md` проходить Constitution Check за принципами I–VI.
Зміни конституції — через `/speckit-constitution` з оновленням версії (MAJOR — прибрано або переписано принцип,
MINOR — новий принцип чи розділ, PATCH — уточнення формулювань).
